## 機能要件
### データ
- 初期状態として INDI の `@I1@` を起点ノードとしてスタート
  - SUBM と INDI は無関係(SUBM はファイルの提出者情報のみ)
- サンプル .ged を同梱し、初回起動時に読み込む
- .ged ファイルのインポートが可能
- 編集中のデータは localStorage に保存し、リロード後も復元する

### レンダリング
- 日本式の家系図表記
  - 婚姻関係は二重線
  - 兄弟姉妹は横に並べる
- 選択中のノードを中心に上下2世代を表示
  - ノードをクリックすると、そのノードを中心に再描画する
- 再婚時は配偶者を上下に連ねて表示

### 個人ノード操作
- レンダリングされた家系図から個人ノードをクリックすると以下の効果
    - 画面右半分にその個人の詳細情報を表示
      - 下部のボタンより編集・閲覧モードをトグル
      - スマホでは画面下部からのシート表示(shadcn/ui Sheet)
    - ノードの右側にメニューを表示
      - 親を追加
        - 父母がすでに揃っている場合は表示しない
      - 配偶者を追加
      - 子を追加
- 既存ノードを選択し、個人ノードを追加/編集/削除可能

### 削除ルール
- 削除により家系図が分断される(矛盾が発生する)場合は削除を禁止
- 起点ノードの削除は禁止
- 削除の結果メンバーが0人となった FAM は自動で削除
  - 夫婦の片方のみ・子なしの FAM など、メンバーが1人以上残る場合は削除しない

### エクスポート
- .ged, .pdf, .png の形式でエクスポート可能
- エクスポート対象データ(現在のデータ/フィルタ後データ)は注入とし、エクスポート処理とは疎結合にする
  - v1 時点ではフィルタ機能自体は実装しない(展望参照)
- PDF は canvas の画像を埋め込む方式(jsPDF)
  - 文字選択可能な PDF は任意(できれば対応)

## 実装要件
- GEDCOMバージョン7.0.18(開発時点の最新)
- 初期で許可する要素(GEDCOM 7.0 の構造に準拠)
  - HEAD
    - GEDC
      - VERS
    - SUBM(SUBM レコードへのポインタ)
  - SUBM
    - NAME
  - INDI
    - NAME
      - GIVN
      - SURN
    - SEX
    - FAMS
    - FAMC
  - FAM
    - HUSB
    - WIFE
    - CHIL
  - TRLR
- 7.0 では文字コードは UTF-8 固定のため HEAD.CHAR は扱わない
- HEAD.GEDC.VERS が 7.x 以外のファイルはインポート不可
- エクスポート時の VERS は `7.0`

### インポート・エクスポート
- 許可リスト外の要素は内部に保持し、UI では表示・編集しない
  - .ged エクスポート時にそのまま出力する(他ソフト由来のデータを失わない)
- 個人名
  - UI は姓・名の2入力
  - 出力は NAME `名 /姓/` と GIVN・SURN の両方
  - 読込は GIVN/SURN を優先し、無ければ NAME の `/姓/` 表記から分解
- 整合性
  - 存在しない xref への参照、HEAD/TRLR の欠落はインポート失敗
  - 片方向のみのリンク(INDI.FAMS ↔ FAM.HUSB/WIFE、INDI.FAMC ↔ FAM.CHIL)は双方向に補完し、警告を表示
- 起点ノード
  - `@I1@` が存在しない場合はファイル内で最初の INDI を起点とする
  - INDI が0件の場合は空状態から1人目の作成を促す
- 細則(フェーズ1実装時に決定)
  - `@VOID@` ポインタはリンク無しとして扱う
  - INDI の2つ目以降の NAME・SEX は許可外要素と同様に保持する(別名等)
  - FAM の HUSB/WIFE の重複、SEX の値が M/F/X/U 以外はインポート失敗
  - 片方向 FAMS の補完先は SEX が M なら HUSB、F なら WIFE、それ以外は空いている枠(HUSB → WIFE の順)。枠が埋まっていればインポート失敗
  - 許可外要素の参照(ポインタ)は検証しない
  - エクスポート時の並び順は HEAD → SUBM → INDI → FAM → 許可外レコード → TRLR。各レコード内は許可要素 → 許可外要素の順(元ファイルの並び順は保持しない)

### `packages/gedcom` の構成
- `syntax/`: タグの意味に関与しない構文層(行の解析・CONT 結合・`@@` エスケープ・シリアライズ)
- `model/`: 許可要素を型付きモデル(`FamilyTree`)に変換する層。許可外要素は `extras` / `extraRecords` に保持
- カスタム要素の追加時は `model/types.ts` に項目を追加し、`import.ts` / `export.ts` の対応タグを増やす。未対応のうちは `extras` に保持されるため、追加前のデータも失われない
- 描画ライブラリは react-konva
- UI 言語は日本語のみ
- スマホ対応必須

### フェーズ1: GEDCOM パース・シリアライズ・モデル変換
#### 実装内容(`packages/gedcom`)
- `src/syntax/`(構文層)
  - `line.ts`: 1行の解析・整形(`parseLine` / `formatLine`)。`@@` エスケープ、`@VOID@` の扱い
  - `parse.ts`: `parseGedcom` 文字列 → `GedcomNode` 木。BOM 除去、LF/CRLF/CR 対応、CONT 結合、level 飛びの検出
  - `serialize.ts`: `serializeGedcom` 木 → 文字列(改行 LF、末尾改行あり、改行を含む値は CONT に分割)
  - `types.ts`: `GedcomNode`、`GedcomSyntaxError`(行番号付き)
- `src/model/`(モデル層)
  - `types.ts`: `FamilyTree` / `Individual` / `Family` / `Submitter` / `Header` / `Link`、`GedcomImportError`
  - `name.ts`: 個人名の読込(GIVN/SURN 優先)・出力(NAME と GIVN/SURN の両方)
  - `import.ts`: `importGedcom` 文字列 → `{ tree, warnings }`。参照検証、片方向リンクの補完
  - `export.ts`: `exportGedcom` モデル → GEDCOM 7.0 文字列
  - `root.ts`: `findRootId` 起点ノードの決定
- 仕様上の判断は「実装要件 > インポート・エクスポート」「`packages/gedcom` の構成」に記載
