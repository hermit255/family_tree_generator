## 機能要件
- 人物に写真(アバター)を設定できる
- 保存は現行の方式(localStorage に GEDCOM 文字列、エクスポートした .ged)を維持し、写真もその中に含める

### 細則(フェーズ1実装時に決定)
#### 保存方式の検討
- 写真をそのまま保存すると localStorage の容量(ブラウザごとに約5MB)を1〜2枚で超えるため、ブラウザで縮小してから保存する
- 縮小した写真を GEDCOM の `OBJE` レコードに data URI で埋め込む。GEDCOM 7 は1行の長さに上限が無く、.ged 1ファイルに写真を含められる
- 他のソフトとの互換性を優先する場合の標準は GEDZIP(.gdz: .ged と画像ファイルの ZIP)だが、ZIP の扱い・IndexedDB への保存・.gdz の読み込みが必要になり工数が大きいため対象外とした(将来検討)

#### データ(GEDCOM)
```
0 @I1@ INDI
1 OBJE @O1@
0 @O1@ OBJE
1 FILE data:image/webp;base64,....
2 FORM image/webp
```
- 人物が参照する `OBJE` のうち、最初の `FILE` が `data:image/...;base64,` の data URI である最初のものを写真とする(1人につき1枚)
- 外部 URL の `OBJE`、ポインタを持たない `OBJE` などは従来どおり未対応の構造として保持し、そのまま出力する
- モデルの型は変えず、写真は `Individual.extras`(INDI 下の `OBJE` ポインタ)と `FamilyTree.extraRecords`(`OBJE` レコード)から読み取る。インポート・エクスポートの処理は変更しない
- 写真の `OBJE` レコードの xref は `O<n>` で採番する
- 写真の設定: 新しい `OBJE` レコードを追加する。写真が無ければ人物の下位構造の先頭から参照し、あれば同じ位置の参照を差し替える
- 写真の削除・差し替え・人物の削除で、どこからも参照されなくなった写真の `OBJE` レコード(data URI 画像のもの)は削除する。他の人物・レコードから参照されている写真や、外部 URL の `OBJE` は残す

#### 写真の縮小
- 画像ファイル(`image/*`、20MB まで)を中央で正方形に切り抜き、192px 四方に縮小する(元画像が小さい場合は拡大しない)
- WebP(品質0.8)で保存する。WebP を出力できないブラウザでは JPEG(品質0.8)にする
- 1枚あたり十数KBになり、数百人分を保存できる

#### 画面
- 詳細パネルの閲覧モードの先頭に写真(無ければ人物のアイコン)と「写真を設定」(写真があれば「写真を変更」)・「写真を削除」を表示する。写真の削除は確認ダイアログを経る
- 写真の設定・削除は編集モードを経ずにすぐ反映する
- 家系図のノードは大きさを変えず、写真のある人物は左端に 36px の円形の写真(性別の色で縁取り)を置き、名前を右へずらす。画像(PNG・PDF)出力にも写真を描く
- localStorage への保存に失敗した場合(容量超過など)は、トーストで通知する(写真に限らず全操作が対象。続けて失敗しても通知は1件にまとめる)

- `packages/gedcom/src/operations/avatar.ts`(新規): `setAvatar`・`removeAvatar`、`pruneAvatarObjects`(参照されなくなった写真の OBJE レコードを削除)

- `packages/gedcom/src/operations/tree.ts`: `nextId` の接頭辞に `O` を追加
- `apps/web/src/features/family-tree/avatar-image.ts`(新規): `resizeAvatar`(縮小)、`loadImage`(data URI 画像の読み込み・キャッシュ)、`useLoadedImage`(読み込み完了後に返すフック)、`AvatarImageError`
- `apps/web/src/features/family-tree/layout.ts`: `LayoutNode.avatar`(写真の data URI)を追加
- `apps/web/src/features/family-tree/tree-shapes.ts`: `personShapes` に写真の配置を追加し、写真のある人物の名前をずらす。`AVATAR_SIZE`・`AvatarShape`・`squareCrop` を追加
- `apps/web/src/features/family-tree/components/tree-canvas.tsx`: ノードに写真を描く
- `apps/web/src/features/family-tree/export/image.ts`: `renderTreeImage` を非同期にし、写真を読み込んでから描く(`export/index.ts` で await)
- `apps/web/src/features/family-tree/components/avatar-section.tsx`(新規): 詳細パネルの写真の表示・設定・削除。`detail-panel.tsx` の閲覧モードに追加
- `apps/web/src/features/family-tree/store.ts`: `setAvatar`・`removeAvatar` を追加。保存失敗時のトースト(`SAVE_FAILED_MESSAGE`)
- `apps/web/src/features/family-tree/storage.ts`: `saveTree` が保存の成否を返すよう変更

#### 設定上の判断
- 計画では `Individual` に写真の項目を追加する案もあったが、OBJE は既に未対応の構造として保持・出力されているため、型を変えずに読み取る方式にした(インポート・エクスポートの変更が不要)
- react-konva の `Image` が jsx-a11y の alt 検査(HTML の img 向け)の対象になり警告が出たため、`KonvaImage` の別名で読み込んだ
- 詳細パネルの写真は、`avatarOf` が毎回新しいオブジェクトを返すため zustand のセレクタで無限に再描画した。比較できる data URI の文字列を選ぶよう修正した
